# ЛР №3 — Многопоточность и синхронизация (Интернет-магазин)

Продолжение ЛР №2: клиент-серверное приложение Интернет-магазина на C# (.NET 10, TCP + JSON).
В ЛР №3 устраняется Race Condition в `CreateOrder` (Часть 1) и реализуется синхронизация
времени клиент-сервер с учетом RTT (Часть 2).

## Состав решения (OnlineStore.slnx)

| Проект             | Назначение                                                                                                                                                                      |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Shared`               | Контракты (`Request`, `Response`, `Product`, `Order`, `TimeInfo`), протокол JSON, интерфейс `IRequestProcessor`                                     |
| `Server`               | Сервер с критической секцией на**lock** (Требования 3–8, Часть 1), операция `TIME_REQUEST`                                     |
| `Server.SemaphoreSlim` | Отдельный проект: та же логика, но критическая секция на**SemaphoreSlim(1,1)** (Требование 9, Часть 1)                 |
| `Client`               | Клиент: меню, смещение часов (`--offset N`), синхронизация времени (Часть 2), режим `scenario` для экспериментов |
| `Tests`                | xUnit-тесты: гонка, параллелизм, SemaphoreSlim, синхронизация времени                                                                            |

## Часть 1 — Race Condition и его устранение

### Анализ гонки (было, в ЛР №2)

В `BusinessLogic.CreateOrder` последовательность «чтение → проверка → задержка → запись»
выполнялась без синхронизации:

```csharp
if (product.Stock < quantity)      // чтение и проверка
    return ...;
await Task.Delay(processingDelay); // 10 с — другой клиент проходит ту же проверку!
product.Stock -= quantity;         // запись по устаревшим данным
```

`await Task.Delay` отдает управление планировщику: пока первый клиент «думает» 10 секунд,
второй успевает пройти проверку по еще не измененному `Stock`, и оба списывают последний
товар (Stock = 1 → −1).

### Критическая секция (Требование 4)

Внутрь синхронизированного блока помещена вся работа с общим состоянием — «проверить
наличие → изменить состояние → подтвердить операцию». Длительная имитация обработки
(`await Task.Delay(10 с)`) вынесена за пределы критической секции: она не касается общего
состояния и не должна блокировать других клиентов. Поэтому клиенты обрабатываются
параллельно (оба END через ~10 с одновременно), а общее состояние изменяется атомарно.

### Реализация на lock (`Server/BusinessLogic.cs`)

```csharp
lock (stockLock)
{
    // START Reserve → LOCK → Available = ...
    if (product.Stock < quantity) { /* FAIL */ }
    product.Stock -= quantity;
    // регистрация заказа
    // SUCCESS | Available = ...
}
// UNLOCK
```

### Реализация на SemaphoreSlim (`Server.SemaphoreSlim/SemaphoreSlimBusinessLogic.cs`)

```csharp
await stockSemaphore.WaitAsync();
try { /* та же критическая секция */ }
finally { stockSemaphore.Release(); /* UNLOCK всегда */ }
```

Отличие от lock: `WaitAsync` не блокирует поток из пула, а асинхронно «паркует» задачу.
`Release` помещен в `finally` — семафор освобождается даже при выходе по `return`/исключению.

### Сценарий проверки

Два клиента одновременно покупают последний экземпляр товара (Id 4, Stock = 1):
`dotnet run --project Client -- scenario 7 4 1 500`.

**Таблица 1 — Результаты эксперимента (2 клиента, Stock = 1, задержка обработки 10 с)**

| Сервер  | Клиент 1      | Клиент 2                                 | Stock после | События в логе сервера                                                                |
| ------------- | ------------------- | ---------------------------------------------- | ---------------- | -------------------------------------------------------------------------------------------------------- |
| lock          | SUCCESS (OrderId 1) | FAIL «Недостаточно товара» | 0                | `LOCK Available=1 → SUCCESS Available=0 → UNLOCK`, затем `LOCK Available=0 → FAIL → UNLOCK` |
| SemaphoreSlim | SUCCESS (OrderId 1) | FAIL «Недостаточно товара» | 0                | идентично: один входит в семафор, второй получает отказ    |

Оба клиента обрабатываются параллельно: `START` разнесены на ~0,15 с, оба `END` через ~10 с.
До синхронизации (поведение ЛР №2) оба запроса завершались SUCCESS, а Stock становился −1.

## Часть 2 — Синхронизация времени клиент-сервер

- Требование 1: смещение часов клиента задается аргументом `--offset N` (секунды; 7 — спешат, −5 — отстают).
- Требование 3: операция `TIME_REQUEST` / ответ `TIME_RESPONSE` с полем `ServerTime` (`TimeInfo`).
- Требование 8: сервер искусственно задерживает ответ на `TIME_REQUEST` на 200 мс (`Program.cs` сервера).

Расчет (метод `Client.SyncTimeAsync`):

```
RTT        = ResponseTime − RequestTime        (по часам клиента)
Delay      ≈ RTT / 2                           (сервер ответил в середине интервала)
Offset     = ServerTime + RTT/2 − ClientTime   (поправка часов клиента)
Corrected  = ClientLocalTime + Offset          (скорректированное время)
```

**Таблица 2 — Синхронизация времени (задержка ответа сервера 200 мс для lock-сервера)**

| Сервер                     | Offset клиента | ClientLocalTime | ServerTime   | RTT        | RTT/2      | Offset        | CorrectedTime |
| -------------------------------- | --------------------- | --------------- | ------------ | ---------- | ---------- | ------------- | ------------- |
| lock (задержка 200 мс) | +7 с                 | 22:38:50.190    | 22:38:42.979 | 206,3 мс | 103,2 мс | −7102,1 мс | 22:38:43.090  |
| SemaphoreSlim                    | −5 с                | 22:39:11.211    | 22:39:16.203 | 5,0 мс   | 2,5 мс   | +4998,5 мс  | 22:39:16.211  |

После синхронизации скорректированное время совпадает с временем сервера
в пределах оценки задержки RTT/2 (расхождение ≈ RTT/2 − реальная односторонняя задержка).

## Запуск

```bash
# сервер (lock)
dotnet run --project lab-003/Server
# сервер (SemaphoreSlim) — альтернативная реализация
dotnet run --project lab-003/Server.SemaphoreSlim

# клиент (меню; часы спешат на 7 с)
dotnet run --project lab-003/Client -- --offset 7

# автоматический сценарий: offset 7, товар 4, количество 1, интервал 500 мс
dotnet run --project lab-003/Client -- scenario 7 4 1 500

# тесты
dotnet test lab-003
```
